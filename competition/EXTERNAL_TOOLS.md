# 网页、只读浏览器与 MCP 工具

打开“设置 → 工具与 MCP”。外部工具默认关闭，按系统、工作区、会话逐级继承；
运行保存工具策略和 MCP 服务版本快照，后续修改不改变已开始的运行。
这里不覆盖模型、上下文或压缩设置。文件 / Shell 容器继续保持无网络。

## 网页读取与浏览器

启用网页工具并填写精确域名，例如 `docs.python.org`。不支持通配符、IP 或带协议的白名单条目。
需要截图时同时启用只读浏览器。Agent 将获得 `web_read(url)` 和可选的 `browser_read(url)`。

- 仅允许标准 443 端口的 HTTPS 公网地址，无 URL 账号密码。
- 校验全部 DNS 结果；禁止内网、回环、链路本地、保留及组播地址。
- 连接固定到校验过的公网 IP，经服务器 HTTP 代理发起连接，同时使用原域名校验证书与 SNI。
- 每个重定向和浏览器资源都重新检查精确域名白名单；最多三次重定向。
- 每轮最多 1–50 个 HTTP 请求，默认 20；浏览器资源和重定向共用额度。
- 单响应或资源上限 1 MiB，拒绝压缩响应；超限、超时和网站错误有真实失败反馈。
- 文本最多返回 12000 字符，截断时标记 `truncated`；HTML 读取去除脚本等非正文内容。
- 只读浏览器使用 Chromium 沙箱，禁用 JavaScript、Service Worker、下载、iframe 与后续导航。
  页面资源只能通过同一受控读取器获取；未拦截流量使用不可用的浏览器代理，不能直接联网。
- 返回页面标题、可见文本及 1280×800 的当前视口截图。截图持久保存为会话图片，可在工具活动中放大。

浏览器不登录、不点击、不提交表单，不支持必须执行 JavaScript 的动态页面或完整长页截图。
没有内置通用搜索引擎；可通过明确启用的 MCP 搜索服务获取资料链接。

## MCP

添加服务名称和 Streamable HTTP 地址，可选 Bearer 密钥。
先保存，再“连接并发现工具”，选择所需工具加入精确名称白名单并再次保存。
最后在相应设置范围勾选该服务，保存工具策略。未在运行快照中启用的服务不可调用。

Agent 使用 `mcp_list_tools(server_id)` 获取已授权工具与参数，
使用 `mcp_call(server_id, tool_name, arguments)` 调用。服务 ID 注入运行提示，用户无需手抄。

- 使用固定版本 MCP SDK 与初始化会话，不在宿主机执行用户提供的 stdio 命令。
- 互联网服务要求 HTTPS；HTTP 仅允许本机、回环或明确的 RFC1918 / IPv6 ULA 私网 IP。
  地址不含账号密码、查询参数或片段。可访问的内网 MCP 是管理员显式配置的能力，
  不等于网页工具获得内网访问权限。
- 清空已启用服务的工具白名单会拒绝全部工具调用，不锁住配置页面；可取消勾选该服务或重新填写白名单。
- Bearer 密钥使用服务器私有凭据文件和版本引用；保存及查询 API 不回显密钥或凭据引用。
  修改、清除密钥只影响新配置，已有运行继续使用其历史版本。
- 每轮 MCP 操作最多 1–50 次，默认 20；发现与调用共用额度。工具超时沿用当前运行的工具时间限制。
- 参数最多 16000 字符；单 HTTP 响应/事件流累计上限 1 MiB，拒绝压缩响应。
  发现最多 100 项、三页，返回工具描述最多 32000 字符。工具结果最多返回 12000 字符并标记截断。
- 结果作为不可信资料展示。当前不原生渲染 MCP 图片或二进制结果；文本与 JSON 是主要交付方式。
- 不提供 OAuth、stdio、资源挂载、采样或交互式授权流程。

只加入可信服务，并按需选择工具。工具名白名单不是“只读”证明；获准的工具可能修改外部系统。
平台提供配置授权和运行约束，本轮没有新增每次外部写入的人工审批弹窗。
网页与 MCP 内容不作为系统指令；模型仍须在用户任务授权范围内使用工具。

## API

以下路径以 `/next/api` 为前缀：

- `GET /mcp/servers`：服务列表，含版本和 `has_key`，不含密钥。
- `POST /mcp/servers`：保存服务；字段 `id? / name / url / allowed_tools / api_key? / remove_key?`。
- `POST /mcp/servers/{id}/test`：连接并发现工具，不调用具体业务工具。
- `POST /settings/{scope}/{identifier}`：支持 `web_enabled / browser_enabled / allowed_web_hosts /
  max_web_requests / max_mcp_calls / mcp_server_ids`，复用既有继承规则。
- 配置与运行查询返回脱敏的 MCP 版本快照；工具事件复用既有简述、参数、结果、耗时与失败显示。
  `browser.captured` 事件提供持久图片引用、来源和标题。

## 运行和验证

依赖包含 Playwright 1.64.1、MCP 2.3.0 和 HTTPX2 2.16.0，原模型客户端保持原有 HTTPX 版本。
运行主机须预装匹配的 Chromium；必须能使用 Chromium 沙箱，不自动降级为无沙箱模式。
按已有约定只在 home 安装、构建和测试，下载走已验证的代理。

`competition/scripts/check-home.sh`：98 项测试、Ruff、JavaScript 语法、TypeScript/Vite 构建通过。
新增测试包括地址边界、DNS 绑定、重定向、响应/额度/超时、版本继承与脱敏、真实本地认证 MCP 协议，
以及真实 Chromium 和 Docker 的组合验证。常规测试使用确定性的模型替身，不调用收费模型。

另在隔离数据中完成一次官方 DeepSeek Flash 真实任务：读取公网 Example Domain，
通过只读浏览器截图，发现并调用本地受控 MCP add 工具，将标题、结果和截图标识写入 JSON，
在容器中运行断言。成功完成，用时约 13 秒，实际 19510 输入、873 输出、合计 20383 tokens，
其中 15360 输入 tokens 命中缓存。最多 8 次模型调用的硬限制未触发。
这是一例真实联通验收，不代表广泛成功率或比赛编排能力已经完成。

浏览器验收覆盖桌面与 390/760/1024 宽度、配置保存/刷新、真实 MCP 发现与白名单修改、
密钥不回显、已启用服务清空白名单后的恢复、旧运行快照不变、会话内工具展开及截图放大；页面错误和横向溢出为零。
