# 工作区项目与文件交付

在工作台左侧点击“工作区文件 / 导入项目”，或在顶部点击“文件”。

## 导入已有项目

选择一个普通 ZIP，填写名称并点击“导入为新工作区”。导入保留 ZIP 中的
相对目录结构，成功后切换到新的工作区。关闭文件面板、新建会话，即可让
Agent 阅读和修改导入的文件，执行工具并验证结果。现有工作区不会被覆盖。
不要把依赖目录、.git 目录、链接或不需要的私密文件加入 ZIP。

ZIP 上限 8 MiB，解压后合计上限 32 MiB，单文件最多 16 MiB，最多 1000 项，
最多 20 层目录。不支持加密、链接、特殊文件、重复文件名和冲突路径。
导入前完整验证内容；文件写入全部成功后才登记工作区，失败会清理新目录。
上传文件使用私有读写权限，不保留 ZIP 内的可执行权限或其他特殊权限。

## 浏览与下载

工作区内所有会话共享文件。点击目录进入，点击文件查看 UTF-8 文本，
点击“上一级”返回；文件列表和当前预览每 5 秒刷新，也可手动刷新。
二进制文件及大于 256 KiB 的文件显示下载提示。文本仅作为纯文本展示。
可以下载单个文件，或将工作区普通文件及目录导出为 ZIP。

单文件下载上限 16 MiB；工作区导出最多 1000 项、32 MiB 未压缩内容，
ZIP 成品最多 32 MiB。导出不包含链接和特殊文件。文件改变时刷新可见；
导出期间仍可能发生修改，因此 ZIP 不应作为运行中工作区的一致性备份。
链接不提供预览和下载。路径始终限制在选定工作区，通过相对目录描述符
和禁止跟随链接实现；不开放服务器任意目录的访问接口。

## API

| 方法 | 路径（前缀 `/next/api`） | 内容 |
| --- | --- | --- |
| POST | `/workspaces/import` | `name` 与 ZIP 的 `data_base64`，成功返回新工作区、文件数和字节数 |
| GET | `/workspaces/{id}/files?path=` | 当前目录的文件、目录和不可访问项 |
| GET | `/workspaces/{id}/file?path=` | UTF-8 文本预览或不能预览的原因 |
| GET | `/workspaces/{id}/download?path=` | 作为附件下载单个普通文件 |
| GET | `/workspaces/{id}/archive` | 工作区 ZIP 附件 |

导入使用已有同源校验和 JSON 请求体限制；不存在的工作区或文件返回 404，
不支持的路径、格式或超限请求返回 422，过大的 HTTP 请求体返回 413。
公网访问继续由现有登录入口保护。

## 验证

`competition/scripts/check-home.sh` 执行完整应用检查。
`tests/test_workspace_files.py` 覆盖导入、持久化、隔离、预览、二进制下载、
ZIP 导出、路径越界、ZIP 链接、NUL 文件名、重复路径、路径冲突、大小限制、
目录替换为链接的竞争、特殊文件、写入失败回滚，以及真实 Docker 中的
“导入已有项目 → 读取 → 修改 → 执行验证 → 下载产物”流程。
容器测试使用确定性的模型替身，不发送付费模型请求。
